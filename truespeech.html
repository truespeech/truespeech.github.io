True Speech

truespeech Sandbox

truespeech is a small language for asking precise analytical questions on top of a semantic layer, plus a queryable lexicon of contextual knowledge about the data. The runtime sits in front of the semantic layer in the data stack: database → semantic layer → truespeech.

Type a statement into the top panel. Use compute to run a metric query, register to add a lexicon entry, or check to look up what the lexicon knows about a slice. The runtime parses, validates against the semantic model, generates SQL where needed, and executes against an in-browser DuckDB. Errors are reported with Rust-style caret diagnostics. See the language reference below.

Regions

A region is a contiguous slice of your data, defined by a time range plus any number of dimension constraints. The same region syntax is used by all three constructs (register region, compute, check).

# grammar
over <time-expr> [and <predicate>...]

Time expression

The first clause of over is always the metric's primary time axis, written in a small calendar mini-language:

2026                          -- the year
2026-Q1                       -- a quarter
2026-02                       -- a month
2026-02-15                    -- a day
2026-02-03 to 2026-02-10      -- a closed-inclusive range (same unit)
until 2026-Q1                 -- everything up to and including
since 2026-01-15              -- everything from that point onward
all time                      -- unbounded

Additional constraints

After the time expression, additional constraints intersect with and:

and region = 'northeast'
and region in ('northeast', 'west')
and region not in ('midwest')
and ship_date >= 2026-02-01
and ship_date in 2026-Q1                  -- in extends to time containment
and ship_date in 2026-02-01 to 2026-02-28

register region

Adds an entry to the lexicon — a curated fact about a region of the data, scoped to one or more affected metrics, with a natural-language description.

register region <name>
  impacting <metric>[, <metric>...]
  over <time-expr> [and <predicate>...]
  with "<description>"

compute

Runs a metric query over a region. Reconciled against the lexicon automatically — relevant entries arrive alongside the result.

compute <metric>
  over <time-expr> [and <predicate>...]
  [group by <field>[, ...]]
  [order by <field> [asc|desc][, ...]]
  [limit <n>]

Group by

Bare grain words refer implicitly to the metric's primary time:

group by month                -- primary time at month grain
group by region               -- categorical dimension
group by ship_date:week       -- explicit time dimension with grain

check

Looks up matching lexicon entries for a region — no database hit, no metric computation. Useful for asking "what do we know about this slice of the data?" without pulling the numbers.

check <metric>
  over <time-expr> [and <predicate>...]

Semantic model

The semantic model the runtime queries against. It defines two metrics (total_sales and average_order_value) and three dimensions (order_date, region, product_tier) over a single orders dataset. order_date is marked as the primary time dimension — that's what the bare-grain group by month and the calendar-literal forms in over bind to.

semantic_model:
  - name: retail_sales
    description: Sales analytics model for retail operations
    ai_context:
      instructions: "Use this model for sales analysis and customer insights"
    datasets:
      - name: orders
        source: orders
        primary_key: [order_id]
        fields:
          - name: order_id
            expression:
              dialects:
                - dialect: ANSI_SQL
                  expression: "order_id"
          - name: order_date
            expression:
              dialects:
                - dialect: ANSI_SQL
                  expression: "order_date"
            dimension:
              is_time: true
              is_primary: true
            description: Date the order was placed
            ai_context:
              synonyms:
                - "date"
                - "sale date"
          - name: region
            expression:
              dialects:
                - dialect: ANSI_SQL
                  expression: "region"
            dimension:
              is_time: false
            description: Sales region
            ai_context:
              synonyms:
                - "sales region"
                - "territory"
          - name: product_tier
            expression:
              dialects:
                - dialect: ANSI_SQL
                  expression: "product_tier"
            dimension:
              is_time: false
            description: Product tier classification
            ai_context:
              synonyms:
                - "tier"
                - "product category"
              instructions: "Values are 'enterprise' and 'consumer'"
          - name: amount
            expression:
              dialects:
                - dialect: ANSI_SQL
                  expression: "amount"
            description: Order amount in USD
    metrics:
      - name: total_sales
        description: Total gross sales revenue
        expression:
          dialects:
            - dialect: ANSI_SQL
              expression: "SUM(orders.amount)"
        ai_context:
          synonyms:
            - "sales"
            - "revenue"
            - "total revenue"
      - name: average_order_value
        description: Average value per order
        expression:
          dialects:
            - dialect: ANSI_SQL
              expression: "AVG(orders.amount)"
        ai_context:
          synonyms:
            - "AOV"
            - "average order size"
          instructions: "Enterprise and consumer tiers have fundamentally
            different price points; always scope to a specific product_tier
            unless explicitly asked for a blended average."

Database schema

An in-browser DuckDB-WASM instance loaded with ~200 rows of sample sales data spanning January 2025 through April 2026.

CREATE TABLE orders (
    order_id      INTEGER PRIMARY KEY,
    order_date    DATE NOT NULL,
    region        VARCHAR(50) NOT NULL,
    product_tier  VARCHAR(20) NOT NULL,
    amount        DECIMAL(10, 2) NOT NULL
);
